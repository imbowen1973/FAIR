# fair-renderer (Component A)

Renders a `session.md` into an editable, template-bound `.pptx` plus the
two JSON contracts the assembler depends on. Implements Component A of
[`docs/md-to-powerpoint-pipeline.md`](../docs/md-to-powerpoint-pipeline.md);
the input grammar is
[`docs/session-md-format.md`](../docs/session-md-format.md).

## Install and run

```bash
pip install -e "renderer[test]"
```

Six commands ship with it:

```bash
# one session -> one deck
fair-render examples/sessions/session-01.md \
  --template examples/template.pptx \
  --layout-map examples/layout-map.yaml \
  --out-dir out/session-01

# a whole library -> decks, resources + catalog.json
# (template, layout map, framework and credentials are found in the repo)
fair-corpus path/to/library --out _site/data

# an older flat sessions/ library -> a course of blocks
fair-migrate path/to/library --apply

# bind any PowerPoint template; add Cards to one that lacks it
fair-template their-template.pptx --out layout-map.yaml
fair-template their-template.pptx --add-cards their-template-cards.pptx

# check images against the asset policy
fair-assets blocks/

# project a curriculum into SQLite and record completion against it
fair-track sync _site/data/catalog.json --db curriculum.db
fair-track complete --learner ada --block 01-foundations --source pr
fair-track report --learner ada
```

`fair-track` keeps two kinds of table apart: the curriculum is a
projection of `catalog.json` and can be dropped and rebuilt, while
`events` is append-only and the only data not in git. Completion
evidences competencies at the DOK its slides reach, so a credential
needing DOK 3 is not satisfied by DOK 2 evidence.

Outputs, per spec A.4:

- `session-NN.pptx` — deck whose shapes are bound to the template's
  layout placeholders (`<p:ph idx=...>` present in slide XML)
- `slide-id-map.json` — authored slide id → `slideId#creationId`
- `index.json` — semantic index (`sourceRef`, `title`, `develops`, `dok`,
  and `notes`, so a consumer can search narration and not just titles)

A library is a course of blocks — one deck per block, beside the lesson
plans, workbooks and media taught with it. `fair-corpus` copies and
indexes those resources without ever parsing them. See
[`docs/library-format.md`](../docs/library-format.md).

## Acceptance tests

```bash
cd renderer && python -m pytest tests/ -v
```

`tests/test_acceptance.py` encodes spec A.6 one criterion per test:
layout reference, placeholder indices in slide XML, content-to-placeholder
routing, editable `<a:t>` runs, and byte-stable determinism — plus the
creationId contract and layout-map validation.

## Design notes

- **creationId**: python-pptx never writes `p14:creationId`, but
  Office.js `insertSlidesFromBase64` needs it. The renderer injects one
  per slide, derived from `sha256(session:slide-id)` — deterministic, so
  rebuilds keep the same `sourceRef`.
- **Determinism**: output ZIPs are rewritten with fixed entry timestamps
  (`zipnorm.py`); two runs of the same input are byte-identical.
- **Layout-map validation**: every mapped layout name and placeholder
  index is checked against the template at startup; a stale map aborts
  the build instead of writing into the wrong placeholder.
- **Images in non-picture placeholders** are placed at the placeholder's
  exact geometry and the empty placeholder removed; the picture shape
  itself carries no `<p:ph>` (documented exception — picture placeholders
  in the template avoid it entirely).
- **Attribution** rides the render, because rendering is the only path
  from content to deck: a library's `attribution.yaml` (found beside
  `sessions/`) puts a locked funder stamp on every slide, a line in the
  notes, and machine-readable provenance in the slide XML that survives
  re-theming and cross-deck copies. `fair-audit` reads it back.
- `examples/template.pptx` is a stand-in generated by
  `tools/make_template.py`. Any PowerPoint template can replace it —
  the nine Core layouts exist in every stock template, and
  `fair-template` writes the layout map that binds them. See
  [`docs/template-profile.md`](../docs/template-profile.md).
